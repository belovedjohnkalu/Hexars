# Sectioned work

Apply this workflow to every task in the ION repository.

1. Read the latest request and any explicitly named prompt droplets. Turn the authorized scope into a bounded checklist; preserve later corrections and deferrals.
2. Start with short, numbered sections describing the work. Use the same sections for meaningful progress updates. Keep questions, if indispensable, self-contained.
3. Complete each section: inspect the relevant source of truth, implement the working behavior, handle its failure paths, and verify it. A plan, partial scaffold, or untested change is not completion.
4. Continue through every authorized section. Do not use section boundaries as reasons to stop, request repeated permission, or delegate work without authorization.
5. Keep implementation details and checklists out of the product interface unless useful to its users. Sections organize the development work and its communication.
6. Report in concise, named sections: what changed, the verification actually performed, the live link when published, and any remaining blocker. Never claim a deferred or blocked item is finished.
7. For queued prompts, follow docs/prompt-workflow.md: archive original task roots only after verified completion and publication. Preserve permanent ILs and all descendants.

For a tiny answer, one short named section is enough. The user's requested structure takes precedence over the usual preference to avoid headings.
