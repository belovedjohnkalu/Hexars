# ION 0.43 — Rolling Schedule

Completed the existing IL0A1 Schedule, using IL0A11 (2026) and IL0A11A1 (October) as the pattern. All twelve months now contain all their numbered days, and sibling years 2027–2030 contain complete calendars. Existing active IDs, permanent ILs, names and custom descendants are retained. Previously deleted records stay deleted; a missing date gets a new identity rather than recycling an old IL.

The shared tree now contains 1,891 calendar nodes: five years, sixty months and 1,826 days. 2028 has 366 days with February 29; each other initial year has 365 days. Read-only verification confirmed every calendar node has an identifier and the original 2026/October/October22 labels are unchanged. Generation ran through the authorized cloud endpoint, locked the latest workspace and changed version 109→110; it did not replace an old workspace snapshot.

Green means a past year/month/day, white means the current one, and red means future. Comparisons use each account's saved IANA zone, initially detected from its first device; signed-out visitors use their device zone. Colors are projected per viewer rather than written as one global timezone's colors. Exact local-midnight timers and foreground reconciliation update an already-open page. DST is handled by local-date boundaries rather than a fixed 24-hour interval. New Year extends the horizon through current year + four: on January 1, 2027, the tree gains 2031 including January 1, 2031. Past years are retained. Creation occurs on load/visible rollover, so a closed app needs no polling or background worker.

The additive migration adds nullable users.time_zone. Existing accounts remain unset until a signed-in Home request supplies a detected zone; a second device cannot overwrite that preference. No financial records, entitlements or prompt queues were changed. No new settings screen or scheduling features were added.
