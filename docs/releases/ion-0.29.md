# ION 0.29 — Online match words

Online boards show only Forfeit and Draw in their game-action navigation. Other modes retain their eight existing words. Forfeit uses the shared black confirmation sheet. Draw requires a vote from every active player; a played move declines outstanding offers. Votes and match decisions use optimistic version checks, so a simultaneous move or vote cannot be overwritten. Forfeits end the match, with the remaining active players sharing the win in a three-player game. Saved-game views preserve these final outcomes; earlier reviewed positions remain unchanged. Native movement/checkmate rules are unchanged.

Match chat is a participant-only, rate-limited realtime message path. A message is inert text arranged below the board, with the sender's public player name. It has no child, navigation, hold menu, editing or cloud-workspace representation. The app does not persist chat text, replay it on refresh, or include it in Library/shares. Messages expire locally after ten minutes; leaving the view or ending the match clears them. Realtime delivery is transient and cannot replay messages missed while disconnected. A failed send preserves the draft for retry; stable message IDs deduplicate retries. Dev viewers receive permanent identifiers for messages and the two actions, without storing message text in the identifier registry.

Canonical owners: Play + gameCloudLayout for board actions, useCloudGame + game endpoint for versioned game mutations, onlineMatch for consensual/adjudicated results, useMatchChat + match_chat endpoint for ephemeral transport, CloudLayout/cloudText for packing and whole-word lines, Input/Button/Dialog/Spinner for entry and feedback. Existing signed-in player channels authorize delivery; no broad chat subscription is introduced. Chat events do not cause native game refreshes. Email sign-in and match membership remain required. The additive online_state column keeps results outside native board state and changes no existing data.
