# ION 0.49 — Authorship, dev editing and equal Time pricing

Published at https://ion.floot.app. IL09 is Time and IL014 is Library, verified against the permanent registry. No profile-system expansion or unrelated queued prompt was executed.

Holding a posted word opens Controls with its public player name. One batched lookup resolves creators within the already-authorized scope; emails and creator IDs are never returned. Moves preserve authorship, copies use the copying account through the existing creation path, built-in content says ION and missing authors say Member. Existing Journal, Schedule, account and game-history privacy boundaries remain account-bound.

Registered devs can edit shared ION, Chess and Safari content and their own personal spaces. The canonical content editor now has Name, Text and Pictures: change text/color, replace pictures with a collage or remove them. Uploads retain the existing 20 MB/type/signature checks, use a scoped asset UUID and commit with a workspace-version check; browser input cannot specify storage keys, roles or creators. Page text changes are dev-only. Library now permits dev composition; static Time pages do too. Time functions support presentation overrides and hold-to-edit without replacing action IDs. A dev can explicitly choose Delete for everyone after the normal confirmation, while normal Home removal remains personal Hidden/Restore. Hidden recovery infrastructure remains protected. Live balances, counts, memberships and native game state are authoritative data, not free-text edits.

Time has a matched brushed-silver clock with blue rim light on black. Its feature picture and browser favicon on Time pages use the new artwork; the overall ION app/PWA mark is unchanged. Existing root IDs, labels and user content are preserved.

The signed-in denominator now counts distinct real accounts with an unexpired server session, including saved sign-ins. It no longer counts only currently valid browser credentials. Reserved example.invalid QA accounts do not count. Five real accounts qualified at verification, versus three under the previous cookie-based test; the number remains dynamic. Both the displayed count and pricing use the same query. Rolling cookie issuance renews server expiry, and expired server sessions cannot authenticate.

Each paid feature now costs total creation-work Time divided by published paid-feature count, then by signed-in accounts. All 11 published paid products receive the same allocation. Integer microsecond rounding matches ceiling(total / features / buyers). Earlier published direct estimates plus the free-work estimate once form a separately editable baseline: 54,761 seconds at import. Old per-product free allocations are not summed again. Closed timestamped work sessions add to this pool; open sessions do not raise prices. Future catalog prices and affordability use this model. Existing quotes stay valid to expiry, entitlements stay unlocked, the existing free-feature set and free dev access are preserved, and historical ledger entries are unchanged.

Time → Work offers Total, Sessions, Earlier work and Start/Stop. Session timestamps come from the server, not from a client-supplied duration. Devs can correct their completed sessions; the configured owner can correct another dev's work session. All registered devs can revise the earlier baseline with a basis. Corrections are audited, reject stale versions, future ends and overlapping same-dev intervals, and retries do not add time twice. Stopping a session never extends an already-recorded end. These are recorded elapsed dev/agent sessions, not independently verified human labor. Earlier estimates are not assigned invented historical timestamps. Work tracking changes creation costs and does not mint wallet funds. New functional/session clouds receive permanent dev ILs. Catalog invalidation refreshes Work across devices.

This implementation's agent work interval was started at the first observed UTC clock timestamp, 2026-10-23T06:39:04Z, and is closed once at the final verified end. Earlier advisory conversation and previous work are not retroactively timestamped. The baseline remains editable for missing or mistaken historical estimates. Administrative close queues the existing Home refresh, which also invalidates the Time catalog.
