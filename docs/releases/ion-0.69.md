# ION 0.69 — Chess hub, community and capacity hardening

## Chess experience

Chess presents Play, Learn, Library and Community in the existing organic/tiled navigation. Continue is visible for this account’s unfinished device match. Learn adds a first-game guide and a daily idea using existing complete rules and illustrations. Empty unfinished default sections stay out of ordinary users’ menus; dev/custom content remains. Library loads only where needed. Automatic game caches and discussion drafts are account-scoped; another account’s or an old global cache is not silently adopted. Existing signed-in games and explicit capability links remain accessible.

Community has five editable areas, private Following and Be kind. Read without signing in; sign in to post, follow or report. Topics/replies use bounded keyset pages preserving timestamp microseconds, permanent public ILs, actual descendant-character sizing, idempotent writes, versioned edits and per-account throttles. Distinct topic/reply namespaces prevent UUID collisions with clouds. Live reply events include count deltas for their topic only. Hidden text never broadcasts publicly. Reports, hidden-content inspection and settings are registered-dev only. Devs can pin, close, move, hide and restore discussions, pause posts, change cooldowns and adjust protected native admission limits. New cloud/action labels remain editable through ordinary Controls and Words.

Deletion requires confirmation and offers an account/version-bound signed undo for ten seconds. Failed sends retain their words through reload. Following and direct IL links open the actual discussion/reply. Community’s default arrangement uses both axes rather than a phone column. Long titles and bodies use the canonical measured reader; short landscape screens open replies separately. Inter, the light default, saved dark first paint, optional tiling, reduced motion and the existing flat native boards are retained.

## Backend and peak handling

One reference-counted realtime connection serves mounted features in a document; switching accounts retires the old grants. Reconnect uses jitter/backoff. Removed waiting-room/catalog polling and redundant session writes reduce request amplification. Buyer-count batches patch exact prices locally rather than refetching every catalog. Ownership and affordability changes still refresh discovery. Financial earning leases and append-only settlement are preserved.

Anonymous Home/Chess/Time share a 15-second durable origin snapshot, with a leased on-demand refresh, stale reads and guarded invalidation. Private content and authority never enter that snapshot. Native starting positions and validated board views are cached by build. Read-only game fetches omit full historical timelines. Durable per-game operation leases reject duplicate expensive searches; separate rules/search admission pools protect shared capacity. Online matches use account/room and ordered variant locks rather than an app-wide mutex. New games and memberships commit together. Failed post-commit broadcasts do not turn saved moves into reported failures. Daily bounded housekeeping does not delete saved games or content.

Manage measures signed-in players returning on a later UTC day within seven days of first observed Chess play. Measurement starts now, excludes reserved QA users and requires cohorts to mature after seven days. Ten percent is a target, not a guaranteed outcome.

**Million-concurrent readiness is not certified.** The current Pro deployment has not received a provider quota reservation, database resize or million-client distributed load test. The existing 15-second monetary earning lease is a separate major constraint. Admission caps protect the app; they do not create compute resources. [The launch capacity document](../chess-launch-capacity.md) gives explicit demand assumptions, limits and staged proof requirements. A staging-only k6 script and a non-network planning model are checked in. No live load generator was run.
