# ION 0.41 — Contents determine font size

CloudTree already excluded a cloud's own name from its character weight. CloudLayout nevertheless used all label measurements to limit the page's font ceiling. That indirect dependency is removed: the viewport and descendant percentages choose typography first, and name measurement only reserves space afterward. Renaming a cloud cannot change its own or sibling fonts. Names within a cloud continue to count as that ancestor's contents. Empty leaves remain equal. Long labels still wrap at eight words and remain accessible through panning; no text is truncated or IL changed.

The shared color slider previously focused its thumb during touch value changes, taking focus from the typing field and dismissing its mobile keyboard. CloudColorWheel now opts into a shared Slider behavior that preserves an active text input in the same form for touch/pen drags. Pointer capture drives the controlled color value without moving focus; caret, selection and draft remain. Disabled/cancelled gestures are respected. Mouse and intentional keyboard slider interaction retain Radix behavior.

The same fixture renamed a cloud to a 480-character single-word name, saved it through controlled endpoint responses and confirmed all sibling computed font sizes/percentages were unchanged. Unit tests additionally cover empty leaves, deep-content growth, captions, disabled/cancelled drag and slider arrow keys. Browser account/cloud responses were fixtures; no real account contents, financial records or prompt branches were mutated. Headless Chromium confirms focus continuity; a physical iPhone keyboard was not directly observed.
