# ION 0.33 — Word allowance and page views

CloudComposer shows an active word counter beside the typing field. Public/Private totals follow the existing doubling allowance and include 1,000 words for each attached picture. The chooser appears only when another picture fits. Selected pictures retain preview/removal and upload cancellation; invalid totals are blocked before upload and on every server mutation/transfer. Existing text/photos are grandfathered rather than deleted. Other editable spaces retain their existing label policy.

Cloud hierarchy statistics now include word-equivalent weights, propagated through every descendant and through Home's scope summaries: each picture contributes exactly 1,000 words, and each collage picture counts separately. Unicode character statistics still provide the existing continuous size refinement; deletion counts stay independent. This is visual/entry accounting only, with no effect on Time prices or balances.

FloatingBack and Left history navigation skip Controls and duplicate same-page return entries. A direct Controls fallback resolves its safe origin. Visited routes remain the source of truth; hierarchy is only the direct-entry fallback. Saving a linked game no longer clears the router history index. Downward board swipes flip or perform the existing pre-move side switch; upward swipes have no such action. Horizontal history, keyboard-accessible F and the existing pass-and-play turn perspective are preserved.

On fine-pointer/hover desktops, plain Up creates a page view and Down removes the newest one. The sequence is 1, 2, 3, 4… views. Two start stacked; three use a larger left view and two right views, then the largest area is subdivided with golden proportions. Down reconstructs the previous geometry. A pane starts at the focused page's current URL and navigates independently. The primary route stays mounted, preserving its state. New views are same-origin page frames with independent responsive viewports, shared server-authorized data and the existing per-account single earning lease. External redirects still open a separate tab. No new app/account/database is created.

Only the app's own frame windows can send split/close messages, with exact origin/source checks. A page frame does not create nested workspaces. Arrow capture yields to IME, native editing, nonempty composers, dialogs, sliders, menus, modifiers and chess-cell navigation. Touch devices do not split. A minimum readable pane size prevents unusable partitions. Unsaved photo drafts block closing their pane; saved/text drafts retain the existing policy. Reduced motion removes pane/line transitions. White separators have a soft glow and rounded ends and stop short of the outer edge.

Validation: hosted TypeScript is clean; 17 targeted Jasmine files passed, covering pictures/word limits, layout, composer, Back, split geometry/key handling, history, game state/side switching, transfers and shared mutation state. Preview browser checks passed for the live counter, picture eligibility/selection/removal, Controls-free Back, phone typing and downward-only real-board rotation. DESIGN.md lint has zero errors/warnings. The strict static audit reports pre-existing Form-provider and Button-asChild false positives; the underlying native forms have noValidate, and linked buttons are functional. Nested preview frames use Floot’s preview loader, so independent page-frame loading is verified separately on production before sign-off.

Production checks passed for independent two/three-page navigation and reversing to the mounted original page. An unchanged legacy picture can be restored with Undo even if it predates the depth allowance; new copies still enforce the current budget. Automatic filename captions are included in live totals.
