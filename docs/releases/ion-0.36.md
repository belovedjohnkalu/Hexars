# ION 0.36 — Dev population and prompt workflow

Dev Accounts (IL05) now shows Signed in with the current number of unique accounts holding valid issued credentials. It uses the exact server count that divides approved creation costs, counting devs and each account once across devices. Session issuance, logout and password reset publish the existing catalog invalidation; visible dev Accounts pages reconcile every five seconds for silent credential expiry. Focus/reconnect refresh and existing error/retry states remain. The label can be edited without persisting a stale numeric value. Regular account seeds and API responses omit the counter and its numeric field.

Prices were investigated without changing estimates, ledger entries, wallets or entitlements. There were four signed-in accounts. Defensive's approved direct estimate was 1,200,000,000μs plus 4,003,000,000μs allocated free work, yielding 1,300,750,000μs per buyer (21m 40.75s). A larger signed-in population lowers this price by design; the latest recorded cost revision increased Brusky's estimate rather than decreasing it. A historical price drop cannot be quantified without a previous population snapshot.

IL0A0 is the existing To do branch. It and every descendant are filtered on the server for guests and non-devs before image URLs are generated. Redirect resolution uses the same filter. All devs can read it; the configured Home owner remains the only account authorized to edit it. Permission follows immutable IDs and parent relationships, not editable names. Existing public sibling Completed at IL0A1 is preserved.

The requested IL0A00/IL0A01 arrival slots were unused. The data patch adds Prompts (IL0A00), Completed (IL0A01) and a Complete ready queue inside Prompts (IL0A000), with new permanent identifiers only. It locks the current Home row and identifier allocation, rejects changed arrival slots and appends rather than replacing a prior snapshot. See [prompt workflow](../prompt-workflow.md) for the bounded active-session process: implement only prompts under an exact Complete cloud in IL0A00, verify them, then move their original roots to IL0A01 without renumbering. No unattended server text execution is introduced.

Preview browser checks pass for five-second count updates, phone layout, retaining the last count on failure, Retry, and existing Time/price/Receive/reset flows. No QA accounts were created, avoiding changes to the pricing population.
