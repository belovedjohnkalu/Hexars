## Spaces and authority
Home starts with Hexagonal Chess, Public, Private, Controls and Accounts. Dev accounts can insert additional Home clouds; ordinary accounts cannot. Public and Chess are globally readable, including signed-out visitors. Posting in Public requires sign-in; authors edit their own entries, and dev accounts can moderate. A branch containing somebody else's contribution cannot be moved or deleted by a non-dev. Private always requires an authenticated session and resolves only that account's workspace; supplied IDs or legacy capabilities never confer another account's access. Only explicit ion_dev_accounts members can change Home, Chess, Controls or Accounts, including their system functions. Existing configured owner membership is seeded once. An admin role alone is insufficient. Accounts customizations belong to the current account; shared Home and Chess changes are public. Dev membership never grants access to another account’s Private space. Home counts do not reveal another account's private content.

Every confirmed word/picture is server-persisted. Each cloud allows exactly 1,024 immediate children; no lower cap, no fixed nesting or whole-workspace count cap. Add, copy, move, restore and transfers enforce capacity server-side without deleting existing data. Private names have no 80-character cap; Public and dev-created Chess names remain 1–80 characters. Compact previews do not modify stored text; opening a long name exposes its full text in fitted pages. pictures PNG/JPEG/WebP/GIF up to 3 MB. Picture upload keys include workspace and author IDs. Private signed image URLs are returned only after scoped authorization. Old guest content can be explicitly joined to its first signed-in owner, remains Private, and is never automatically published. Shared realtime grants are exact home/public/chess channels; Accounts grants contain only the current account’s channel; private grants contain only the authenticated user's channel. Focus/reconnect reconciles authoritative state. Account changes discard old response/cache state.

## Hierarchy and correction
One parent per node. Count all descendants; compare visible siblings only. Ties share equal sizes and zero stays readable. Backend rejects moves/copies to self or descendants, missing/removed parents, stale writes, and identity collisions. Public ↔ Private transfer locks both workspaces, checks both versions, preserves node identities for a move, remaps them for a copy, and records an idempotent operation. Copy preserves the source; move removes its old placement. Publishing confirmation explicitly says everything inside becomes public. Copies already made by others remain after a public source is moved away. Shared pictures remain attached to copied branches. Soft deletion within a space retains images; Undo remains visible only until ten seconds after the original deletion timestamp; reload never extends it. Confirm before removing a branch; focus Keep cloud. Text drafts are scoped by account/space/cloud; picture drafts remain in memory with an unload guard. Retry retains input and IDs.

## Navigation and camera
The URL's cloud and space parameters own hierarchy. SpatialViewport owns transform-based panning, pinch, modified-wheel and keyboard zoom. There is no native app scrolling. Rules and long menus use shared fitted text/pages. The Public/Private and dev-only Chess gradient wheel is the shared keyboard-accessible Slider, with a continuous spectrum and a 44px target, not a scroll container. Pointer or keyboard selection skips exact sibling RGB duplicates. The server allocates against current versioned siblings too, including seeds, and concurrent writes retry safely. Existing colors, name-only edits and branch copies remain intact; different clouds may reuse colors. No perceptual-distinctness claim is made for neighboring shades. There are no visible zoom controls. Camera is remembered per cloud. Rules fill a square canvas and start at readable scale instead of fitting every word into a phone-width column. Initial fitting waits for data and font readiness. Deletion, undo, and realtime updates preserve the current camera; retained label centers stay anchored unless changed dimensions cause a collision. A removed word’s dialog returns focus to the word-space region, avoiding a header jump. BoardPreview contains every native board within the reserved picture frame, leaving its caption separate. Background drags must not activate words; holding for 300 ms, right-click or Shift-F10 navigates to Controls, where action droplets open permitted Edit/Move/Copy/Delete dialogs. Pointer movement over 8 px cancels holding. Release clicks are suppressed across navigation; pointer-down does not focus or invoke native callouts. The title is plain text and opens no popup. Back is bottom left and restores the originating word. The top-left Home shortcut opens Private, Public or Hexagonal Chess from any depth; pressing it at that scope root opens ION. Home has fixed anchors and waits for initial data/font readiness. Entering a cloud focuses its heading. The compact composer follows visualViewport height and offsetTop on resize AND scroll, immediately above the phone keyboard. Keyboard resize preserves canvas placement. Inter stays readable; reduced motion removes transitions.

## Destinations
Hexagonal Chess → Engines, Rules, Boards. Boards contains Gliński’s Variant, McCooey’s Variant, Shafran’s Variant, Brusky’s Variant and De Vasa’s Variant with native blue starting-position previews. Each variant under Rules contains a separate colored word cloud for every paragraph; pictures appear only in the opened paragraph, with no Complete Rules wrapper. Tactical opens Pre-Beginner, Beginner, Easy, Medium, Hard, Expert before Boards or the incoming variant. Selection persists and changes native time/depth/node limits. Pre-Beginner is level 0 with 40 ms/125 nodes (half Beginner), depth 1 and a 50% chance to play a random legal move; this is not an Elo claim. Pass and Play clears engine selection and opens the friend slot. Games retain separate engine and pass-and-play slots. Never imply unimplemented variants or engines are available.

## Accounts
Sign in and Create account are explicit URL states; registration never falls back to login. Client/server trim and lowercase email consistently, preserving existing account identity. Password recovery uses separate code and password steps. The account page has one Back action; no redundant Open your space. Remembering an account is explicit. Only a random HttpOnly/Secure/SameSite device cookie is kept in the browser; its hash and valid session associations are in Postgres. No passwords or session tokens in localStorage. Add account preserves the current remembered account; switching requires a valid device association and issues a fresh session. Forget removes quick access; sign-out removes the current association. Expired/revoked sessions cannot switch. A new domain requires signing in again; cloud-backed private content persists.

## Chess
Only the interactive board and Variants, Rules, Engines, Board Reset, Undo and Pass and Play occupy the game void. Blue cells stay flat against the black app. Current turn is a quiet status. Reset with played moves requires Keep playing / Reset board. Swipe right reviews one earlier move; swipe left advances one newer move. Historical requests inspect the saved native timeline and never mutate it. History disables play and offers Present plus accessible previous/next controls. Promotion stays open after a failed request. Piece movement completes before pass-and-play rotation. Result Dialog opens once per ended position: You Win / Tactical Wins or side winner, Stalemate, Draw, with score and View board / Play again. All sheets use black surfaces.

## Accessibility and recovery
Shared-kit semantics, visible focus, keyboard menu access, trapped modal focus, 44px principal controls and readable contrast. Account forms include Forgotten password; no app-owned alert/confirm/prompt. Errors preserve content and offer Retry. Spinner has a stable footprint; no hexagonal loader. Install controls stay hidden when incompatible. No sign-in required just to play chess. Tests: helpers/cloudScopes.spec.tsx, tests/cloud/scopes.api.mjs, tests/e2e/scoped-spaces.live.cjs and chess-results.live.cjs.

## Shafran rules source
The native shared library supplies 70 cells and all legal moves; references and historical-source limits are in docs/variants/shafran.md. Pawn starts permit 1/2/3 steps by file, both crossed en passant cells are valid for a triple advance, and short/long castling is available on either flank when rights and king safety allow. Stalemate scores ½–½; the existing material house draw remains labeled. Rule diagrams use the same native shape and shared blue palette. Tactical levels 0–5, pass-and-play rotation, undo/review, save/resume and mode/level return navigation apply equally to all five variants. No client-provided state loading was added.

## Immediate move feedback
C++ supplies changed cells for each legal move, including en passant, castling and promotion. A pending move paints only these supplied changes; the saved player, ply, result and legal authority do not advance until the API confirms. Errors roll back the preview and offer Retry; version conflicts fetch the current game. Pending boards cannot accept another move. Piece movement takes 220 ms and the following pass-and-play rotation 320 ms. Tactical search budgets remain the selected level’s. Hash/popstate navigation switches saved links, cancels old requests, deduplicates the two browser events, and rejects late responses. Public color edits keep the existing author/owner permissions, persist and publish realtime refreshes.

## Permanent identifiers
Each explicit dev member receives each node’s immutable birth identifier; other sessions receive no identifier field. Shared content and only that dev’s own Private and Accounts workspace are indexed. Home roots are IL0 (Chess), IL1 (Public), IL2 (Private), IL3 (Controls), IL4 (Accounts). A child appends its zero-based arrival segment, with no placeholder zeros: IL1 → IL10 → IL100. Segments use 0–9, A0–Z9, AA0–ZZ9, AAA0–ZZZ9 and continue alphabetically. Persistent counters are serialized under a transaction-level advisory lock. Removed rows retain their assigned identity; future additions never reuse it. Moves retain node IDs and labels, including across Public/Private; copies get new identities. Existing data is initialized from saved order, including removed entries; historical timestamps that were never recorded cannot be reconstructed. Layout reserves label space and labels wrap at their full value.

## Horizontal variants
Brusky’s 84 cells and De Vasa’s revised 81-cell rhombus use native pointy coordinates. Their pawns advance on two edge axes and capture on side vertex axes. Only Brusky grants the virgin pawn’s third capture and lets an immediate enemy block both forward paths. Both support first-move doubles, immediate en passant along either axis, promotion on the opposite horizontal rank, short/long castling, king safety, mate, equal stalemate, repetition and the labeled material house draw. C++ supplies all legal moves and preview changes. Each has 23 separate Rules paragraph clouds; diagrams appear only inside an opened paragraph. Source limits are documented under docs/variants.

The gradient is visible only while the composer form is active; moving focus into its slider preserves it. Dismissing entry retains drafts and does not resize or recenter the canvas.

Game initial fitting waits for native content and measured geometry. Explicit viewport size changes refit; content-only updates preserve the camera. On short landscape screens the board uses the available height and game actions occupy the two side columns.

## Photos and Controls
CloudComposer owns the multiple-file queue, per-file validation and retry identity. Image bytes upload directly to storage, at most three at a time. The server checks presence, size and PNG/JPEG/WebP/GIF signatures before saving one atomic cloud record. Retries preserve completed file IDs only for that same pending cloud ID. CloudPhoto owns the collage; CloudPhotoViewer uses the shared Dialog fullScreen variant and SpatialViewport, with accessible previous/next controls and no app scrolling. The canonical Dialog owns its one close button. Camera and retained label centers are cached across Controls round trips and isolated by account/scope/cloud. Copy IL is available only to dev accounts; clipboard failure provides a selectable field. View photos is available for readable images even if their cloud is noneditable.

Accounts is a cloud of explicit sign-in/create/recover/remember/add/switch/forget/sign-out commands. Ordinary accounts cannot edit these commands; dev accounts can customize their own account workspace. Remembered account clouds contain Open and Forget droplets. Controls and Accounts have reserved photo footprints. Home links into separate scopes; copied scope shortcuts navigate the target and cannot silently create children in the wrong workspace.

## Saved-position retention
Saved chess games expire at 30 days since updated_at (a persisted new game, move or undo). Reads, reviews and settings do not renew them. All saved-game lookups exclude expired rows. Authorized access to an expired capability deletes that row; invalid capabilities cannot trigger deletion. expireSavedGames runs daily at 00:10 UTC through scheduled-jobs.json and physically removes older rows. Explicit expired links show New game; an expired automatic local resume starts a fresh board. Clouds and photos are not subject to this retention.

## Wellisch foundation
Wellisch is not a playable destination. Its separate native foundation covers 91 cells, 45 pieces across three armies, original pawn directions, reserves, turn order and geometric movement. Legal/check/takeover/result rules, serialization and multiplayer search remain pending; do not expose two-player Tactical as a Wellisch engine.
