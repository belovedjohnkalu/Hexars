## Spaces and authority
Home starts with Hexagonal Chess, Public, Private, Controls and Accounts. Dev accounts can insert additional Home clouds; ordinary accounts cannot. Public and Chess are globally readable, including signed-out visitors. Posting in Public requires sign-in; authors edit their own entries, and dev accounts can moderate. A branch containing somebody else's contribution cannot be moved or deleted by a non-dev. Private always requires an authenticated session and resolves only that account's workspace; supplied IDs or legacy capabilities never confer another account's access. Only explicit ion_dev_accounts members can change Home, Chess, Controls or Accounts, including their system functions. Existing configured owner membership is seeded once. An admin role alone is insufficient. Accounts customizations belong to the current account; shared Home and Chess changes are public. Dev membership never grants access to another account’s Private space. Home counts do not reveal another account's private content.

Every confirmed word/picture is server-persisted. Each cloud allows exactly 1,024 immediate children; no lower cap, no fixed nesting or whole-workspace count cap. Add, copy, move, restore and transfers enforce capacity server-side without deleting existing data. Names have no 80-character cap in any space; existing depth-based word budgets still apply. Cloud labels show their full text on one line; opening a long name also exposes its full text in fitted pages. pictures PNG/JPEG/WebP/GIF up to 20 MB. Picture upload keys include workspace and author IDs. Private signed image URLs are returned only after scoped authorization. Old guest content can be explicitly joined to its first signed-in owner, remains Private, and is never automatically published. Shared realtime grants are exact home/public/chess channels; Accounts grants contain only the current account’s channel; private grants contain only the authenticated user's channel. Focus/reconnect reconciles authoritative state. Account changes discard old response/cache state.

## Hierarchy and correction
One parent per node. Count all descendants; compare visible siblings only. Ties share equal sizes and zero stays readable. Backend rejects moves/copies to self or descendants, missing/removed parents, stale writes, and identity collisions. Public ↔ Private transfer locks both workspaces, checks both versions, preserves node identities for a move, remaps them for a copy, and records an idempotent operation. Copy preserves the source; move removes its old placement. Publishing confirmation explicitly says everything inside becomes public. Copies already made by others remain after a public source is moved away. Shared pictures remain attached to copied branches. Soft deletion within a space retains images; Undo remains visible only until ten seconds after the original deletion timestamp; reload never extends it. Confirm before removing a branch; focus Keep cloud. Text drafts are scoped by account/space/cloud; picture drafts remain in memory with an unload guard. Retry retains input and IDs.

Existing colors, name-only edits and branch copies remain intact; different clouds may reuse colors. No perceptual-distinctness claim is made for neighboring shades. There are no visible zoom controls. Camera is remembered per cloud. Rules fill a square canvas and start at readable scale instead of fitting every word into a phone-width column. Initial fitting waits for data and font readiness. ## Accounts
Sign in and Create account are explicit URL states; registration never falls back to login. Client/server trim and lowercase email consistently, preserving existing account identity. Password recovery uses separate code and password steps. The account page has one Back action; no redundant Open your space. Remembering an account is explicit. Expired/revoked sessions cannot switch. A new domain requires signing in again; cloud-backed private content persists.

## Immediate move feedback
C++ supplies changed cells for each legal move, including en passant, castling and promotion. A pending move paints only these supplied changes; the saved player, ply, result and legal authority do not advance until the API confirms. Errors roll back the preview and offer Retry; version conflicts fetch the current game. Pending boards cannot accept another move. Piece movement takes 220 ms and the following pass-and-play rotation 320 ms. Tactical search budgets remain the selected level’s. Hash/popstate navigation switches saved links, cancels old requests, deduplicates the two browser events, and rejects late responses. Public color edits keep the existing author/owner permissions, persist and publish realtime refreshes.

## Permanent identifiers
Each explicit dev member receives each node’s immutable birth identifier; other sessions receive no identifier field. Shared content and only that dev’s own Private and Accounts workspace are indexed. Home roots are IL0 (Chess), IL1 (Public), IL2 (Private), IL3 (Controls), IL4 (Accounts). A child appends its zero-based arrival segment, with no placeholder zeros: IL1 → IL10 → IL100. Segments use 0–9, A0–Z9, AA0–ZZ9, AAA0–ZZZ9 and continue alphabetically. Persistent counters are serialized under a transaction-level advisory lock. Removed rows retain their assigned identity; future additions never reuse it. Moves retain node IDs and labels, including across Public/Private; copies get new identities. Existing data is initialized from saved order, including removed entries; historical timestamps that were never recorded cannot be reconstructed. Layout reserves label space and labels wrap at their full value.
